# KEEL — 텍스트로 관리하는 실시간 협업 다이어그램

아키텍처 다이어그램을 **텍스트로 저장하고 캔버스에서 손으로 고친다.** 저장물이
텍스트라 PR 에서 줄 단위로 리뷰되고, 캔버스에서 노드를 끌면 그 텍스트가 바뀌고,
여러 명이 같은 문서를 동시에 편집한다.

브랜드명 `KEEL` 은 플레이스홀더다.

> 만드는 중이다. 아래 `지금까지 된 것` 이 실제로 도는 범위이고, 나머지는
> `아직 안 한 것` 에 적어 둔다.

## 왜 만드는가

실무는 다이어그램 도구를 하나로 못 쓰고 **draw.io · Mermaid · Excalidraw 를
병행**한다. 병행하는 이유가 그대로 이 도구의 자리다.

| | 손으로 고치기 | PR 에서 리뷰 |
|---|---|---|
| Mermaid / D2 | 안 된다 (레이아웃을 엔진이 정한다) | 된다 (텍스트라 줄 단위 diff) |
| draw.io / Excalidraw | 된다 | 안 된다 (XML·바이너리라 diff 가 무의미) |
| **KEEL** | **된다** | **된다** |

## 문법

```keel
# 주문이 들어와서 결제까지

actor user "손님"
service web "스토어프론트"
service api "주문 API"
db orders "주문 DB"
queue events "이벤트 큐"

group payment "결제" {
  service pay "결제 서비스"
  external toss "토스페이먼츠"
}

user -> web "주문하기"
web -> api
api -> orders "주문 저장"
api -> pay "결제 요청"
api -- events
```

노드 종류는 `service` · `db` · `queue` · `external` · `actor` 다섯 가지,
선은 `->`(방향 있음)와 `--`(방향 없음) 두 가지다. **일부러 이만큼만 둔다** —
문법이 커지면 파서를 완성하는 데 시간을 다 쓰고 정작 실시간과 렌더링을 못 만든다.

`web -> api` 한 줄만 적어도 두 노드가 그려진다. 다만 **오타가 조용히 새 노드가
되는 대가**가 있어서, 선언 없이 만들어진 노드는 진단 목록에 남는다.

## 이렇게 정한 것들

### 위치는 텍스트에 쓰지 않는다

양방향 편집의 핵심 질문은 **"노드를 끌어 옮긴 좌표를 어디에 두는가"** 다.

DSL 안에 `@pos(340, 120)` 으로 적으면 PR diff 가 좌표 변경으로 뒤덮여 "이
다이어그램이 무엇이 달라졌나" 를 못 읽는다. 텍스트로 관리하는 이유 자체가 사라진다.

그래서 텍스트에는 구조만 두고 좌표는 따로 둔다.

- `Y.Text` — DSL 소스. 이것이 문서다. 내보내고, PR 에 붙이고, diff 로 읽는다
- `Y.Map<nodeId, {x, y}>` — 레이아웃. **사람이 옮긴 노드만** 여기 들어간다
- 레이아웃에 없는 노드는 자동 배치(ELK)가 놓는다 — 좌표 없이도 늘 제대로 그려진다

소스만 복사해 가도 다이어그램이 성립하고, 손으로 맞춘 배치는 잃지 않는다.

`{x, y}` 는 노드의 **중심**이다. 왼쪽 위로 잡으면 상자 폭이 라벨에서 나오므로
`api` 를 `주문 API` 로 고칠 때 상자가 오른쪽으로만 자라 노드가 튄다. 이름
고치기는 이 도구의 일급 조작이라 그 튐이 늘 보인다. 이 값은 저장되는 값이라
나중에 바꾸는 것은 코드 수정이 아니라 데이터 이전이다.

### 문서를 통째로 다시 쓰지 않는다

캔버스에서 이름을 바꾸면 **그 이름이 적힌 구간만** 고친다(`packages/dsl/src/edits.ts`).
모든 조작이 `TextEdit[]` 을 돌려주고, 부르는 쪽이 그것을 그대로 Y.Text 에 적용한다.

통째로 다시 쓰면 두 가지가 같이 깨진다 — 사람이 쓴 주석과 줄 순서가 사라지고,
CRDT 에서 **같은 순간 다른 사람이 친 글자가 지워진다.** 통째로 쓰기는 "전부
지우고 전부 넣기" 라서, 상대의 삽입이 지우기 구간 안에 있으면 병합이 아니라
소멸이 된다.

### 파서는 절대 던지지 않는다

사람이 글자를 치는 도중의 문서는 언제나 문법에 어긋나 있다. 깨진 줄은 진단으로
남기고 다음 줄에서 회복한다. 한 글자 쳤다고 화면이 비면 쓸 수 없는 도구가 된다.

검사로 고정해 두었다 — 완성된 문서를 **한 글자씩 잘라 낸 모든 중간 상태**를
파서에 넣어 던지지 않는 것을 확인한다.

### 버전 비교는 텍스트가 아니라 그래프로 한다

줄을 옮기거나 들여쓰기를 고친 것까지 "바뀜" 으로 나오면 정작 무엇이 달라졌는지
안 보인다. `diffGraphs` 는 노드·엣지·그룹 단위로 견주므로, 줄 순서와 주석을
바꾼 것은 **차이가 0 이다.**

엣지의 열쇠에 화살표 모양(`->` / `--`)을 넣지 않은 것도 같은 이유다. 넣으면
방향 표시만 바꾼 것이 "선이 사라지고 새 선이 생겼다" 로 나온다.

### 규칙을 기억이 아니라 검사로 지킨다

Shop 에서 가장 잘 통한 방법이라 가져왔다. **목록을 손으로 들고 있으면 반드시
샌다.** `dsl-roundtrip` 은 손으로 고른 목록이 아니라 `packages/dsl/fixtures/` 를
전수로 돈다 — 픽스처를 넣는 것만으로 검사에 들어온다.

`renderer` 의 전수 검사는 한 걸음 더 나간다 — `packages/dsl/fixtures/` 까지
함께 돈다. dsl 에 `.keel` 하나를 넣으면 렌더러 검사에도 저절로 들어온다
(픽스처 하나를 넣어 검사가 182 → 202 로 느는 것을 확인했다).

그리고 **고친 것을 되돌려서 검사가 실제로 지는지 확인한 뒤에** 커밋한다.
이 확인이 실제로 값을 했다 — 그룹 라벨 띠 검사는 처음에 얕은 그룹으로 썼더니
여백(24)이 라벨 높이(22)보다 커서 **무엇도 묶지 못하는 검사**였다. 깊이 3 으로
바꾸고 나서야 물었다. 여기서 나온 것:

| 검사 | 잡은 것 |
|---|---|
| `지우기 > 마지막 줄과 그 앞줄` | 노드와 거기 걸린 엣지를 함께 지울 때 삭제 구간이 **한 글자 겹쳐** 예외로 죽었다. 가장 흔한 조작이라 반드시 겪는다 |
| `버전 비교 > 화살표 모양` | 엣지 열쇠에 화살표 모양이 들어 있어 방향만 바꾼 것이 "없어짐 1 + 생김 1" 로 나왔다 |
| `그래프 > 그룹을 가리키는 엣지` | 그룹 이름을 끝점으로 쓴 선을 안 거르면 렌더 루프가 없는 좌표를 찾는다 |
| `나란한 선 > 방향이 반대인 선` | 법선을 선 제 방향에서 뽑아, `a -> b` 와 `b -> a` 의 법선이 뒤집혀 벌린 것이 상쇄됐다. 두 선이 겹쳐 그려지고 한 줄을 지워도 화면이 그대로였다 |
| `그리는 순서 ≡ 집는 순서` | 그린 차례와 잡는 차례를 41×41 로 맞대어 본다. 갈라지면 "보이는 것과 다른 것이 잡히는" 상태가 되는데 화면만 봐서는 못 찾는다 |
| `캔버스에 NaN 이 안 닿는다` | 기록된 모든 그리기 인자를 훑는 한 줄. 숫자가 한 번 망가지면 화면 전체가 빈다 |

## 구조

```
packages/
  dsl/         DSL 렉서·파서·프린터 — 위치를 보존한 CST, 구간 수정(TextEdit) API
  graph/       그래프 모델·버전 diff — I/O 없는 순수 함수
  renderer/    장면 기하(좌표·경계·접점·뷰포트·컬링·히트테스트)와 Canvas 2D 그리기
  config/      tsconfig·eslint 프리셋
```

`dsl` 과 `graph` 를 React 와 서버에서 떼어 둔 이유는 하나다 — **I/O 가 없으면
빠르게, 많이 검사할 수 있다.** 나중에 서버가 OG 썸네일을 그릴 때도 같은 코드를 쓴다.

`renderer` 도 같은 규칙을 지킨다. 기하는 DOM 없는 순수 함수이고, 그리는 쪽은
**우리가 실제로 부르는 멤버만 적은 컨텍스트 타입**을 받는다. `lib: ["DOM"]` 을
켜지 않은 덕에 브라우저·Web Worker·node-canvas 가 단언 없이 같은 코드를 쓰고,
호출을 받아 적는 가짜 컨텍스트로 **그리기까지 Node 에서 검사된다.**

## 시작하기

```bash
pnpm install
pnpm test
pnpm typecheck
pnpm lint
```

Node 24 와 pnpm 11 이 필요하다. `.nvmrc` 와 `packageManager` 필드에 고정돼 있다.

## 지금까지 된 것

- `@keel/dsl` — 렉서, 회복하는 파서, 정규형 프린터, 구간 수정 API (테스트 71)
- `@keel/graph` — 그래프 모델, 그룹 중첩, 버전 diff (테스트 16)
- `@keel/renderer` — 장면 기하, 그룹 경계, 엣지 접점·화살촉·자기 고리, 팬·줌,
  뷰포트 컬링, 균일 격자 히트테스트, Canvas 2D 그리기 (테스트 381)

```
dsl 71 · graph 16 · renderer 381
```

렌더러는 아직 **임시 배치**를 쓴다(`stopgap-layout.ts`). 겹치지 않고 결정적이라는
것 말고는 아무것도 약속하지 않으며, ELK 가 들어오면 그 파일을 지운다. 파일
이름에 박아 둔 것은 자동 레이아웃으로 오해하지 않게 하려고다.

## 아직 안 한 것

**만드는 순서대로.** 아래는 계획이지 도는 코드가 아니다.

- **에디터 화면** (`apps/web`, Next.js) — 좌우 분할, CodeMirror 6, 텍스트↔캔버스 양방향
- **실시간** (`apps/api`, NestJS) — Yjs WebSocket 중계, Postgres 업데이트 로그 +
  R2 스냅샷, 구글 로그인, 프레즌스, 오프라인 재접속
- **자동 레이아웃** — ELK layered 를 Web Worker 에서. 키 입력마다 돌리지 않고
  신규 노드만 배치, 전체 재배치는 명시적으로. `stopgap-layout.ts` 를 대신한다.
  **글자는 워커에서 재지 않는다** — 워커의 어림값과 본체의 실측이 어긋나면
  레이아웃이 돌아올 때마다 기하가 밀린다. 본체가 재서 크기를 워커에 넣는다
- **버전 스냅샷 화면**, SVG/PNG 내보내기, 서버 사이드 OG 썸네일
- **커맨드 팔레트와 키보드 전용 조작**, 캔버스 대체 표현(낭독기), 태블릿 제스처
- **PWA** — 앱 셸 precache. 네이티브 앱 패키징은 하지 않는다
- **성능 측정** — 1,000노드에서의 프레임 시간. 재고 나서 숫자로 적는다

의도적으로 범위 밖에 둔 것: 팀·권한·결제·댓글·이미지 업로드·AI 생성.
실시간 서버를 2대 이상으로 늘리는 것(Redis pub/sub 팬아웃)도 빼 두었다 —
인스턴스 1대로 고정하면 같은 문서를 보는 사람들이 갈라질 일이 없다.
